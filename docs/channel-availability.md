# Channel availability

The channel availability page exposes the latest health of explicitly configured channels to authenticated users. Administration endpoints require the admin role. Monitoring is globally disabled by default through `ChannelMonitorEnabled` and should only be enabled after monitors have been reviewed.

## Probe policy

- Text models use the existing channel test path on the configured interval. Results are stored without channel credentials, and public responses omit raw upstream errors.
- Image and video models are never actively generated by this monitor. Their current state is derived from terminal real tasks for the same channel and model.
- Passive matching checks `client_model_name`, `origin_model_name`, and `upstream_model_name`. Queries select terminal metadata only and do not read task payloads or private task data.
- Content or request validation failures, platform storage/worker failures, configuration errors, and unclassified failures do not overwrite the latest effective channel state.

## Passive state rules

Image observations use a 30-minute freshness window. The latest five effective observations are evaluated: a latest success with at least four successes is operational, no successes or three consecutive channel failures is unavailable, and other outcomes are degraded.

Video observations use a 24-hour freshness window because traffic is lower. The latest effective success is immediately operational, one or two latest channel failures are degraded, and three consecutive channel failures are unavailable.

When no effective observation exists inside the freshness window, the state is unknown. Availability percentages use the latest 20 effective image observations or latest five effective video observations within that same window.

## Release verification

1. Keep global monitoring disabled immediately after deployment and confirm migrations created `channel_monitors` and `channel_monitor_results`.
2. As an admin, create one text monitor and one media monitor. Confirm the media monitor reports `media_passive` and that running it does not create a generation task.
3. Enable monitoring, then verify `/api/channel-monitors` exposes only enabled and visible monitors without `channel_id`, channel names, credentials, raw errors, task payloads, or private task data.
4. Confirm a recent media success is reflected as operational and three consecutive channel failures are reflected as unavailable.
5. Verify the `/channel-availability` page on desktop and mobile, including admin configuration and regular-user status views.
