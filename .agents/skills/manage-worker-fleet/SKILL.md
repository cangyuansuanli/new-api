# 管理 Worker 集群

先确定任务状态由谁持有，再操作 Worker。容器、进程或上游临时 URL 都不应成为唯一任务真值。

## 发现运行模型

读取队列实现、任务表、Worker 配置、Compose、部署脚本和监控。确认：

- 任务真值位于数据库、队列还是外部调度系统；
- claim、租约、心跳、超时、重试、幂等键与结算语义；
- API、Worker、调度器、轮询器和协议转换层的职责；
- 并发限制是在全局、节点、账号、模型还是上游维度；
- 节点唯一标识、网络边界、数据库连接预算和对象存储权限；
- drain、resume、reconcile 与死信处理入口。

不要通过增加 Worker 掩盖账号不足、上游限流、数据库锁或错误重试风暴。

## 扩缩容

1. 记录吞吐、队列年龄、成功率、P95/P99 耗时、上游限流和资源基线。
2. 计算新增 Worker 对数据库连接、Redis、带宽、对象存储和上游并发的总预算。
3. 为每个实例配置唯一且稳定的节点名，避免重复身份破坏租约或指标。
4. 先以一个候选实例 canary，限制并发并验证完整任务生命周期。
5. 分批扩容，每批观察至少一个代表性任务周期。
6. 缩容前停止领取新任务，等待在途任务结束或租约安全转移。

跨地域 Worker 只通过受控私网或最小暴露的认证入口访问状态服务。先验证公网不可达，再验证私网可达；已废弃的远程节点、隧道和凭据应从运行配置中移除。

## 发布 Worker

按 `$deploy-container-service` 执行不可变镜像发布。API 和 Worker 共用 schema 时，先建立兼容窗口。若 Worker 持有长任务：

- 先将旧 Worker 置为 drain；
- 等待 active operation 归零并记录超时任务；
- 启动新 Worker 后验证角色、版本、队列连接和心跳；
- 调用已有 resume/reconcile 恢复可恢复任务；
- 确认旧 Worker 不再 claim 后再停止。

协议转换或媒体下载层保持无状态；任务结果、计费和重启恢复由持久化任务层负责。

## 排查

按层定位，不直接重启全部服务：

- **积压增长**：比较入队率与完成率，检查 Worker 心跳和 claim。
- **任务卡住**：查看租约、最后心跳、上游任务 ID、轮询状态和超时策略。
- **重复执行**：检查幂等键、租约过期、节点名冲突和非原子 claim。
- **大量失败**：按错误类型分组，区分本地资源、账号池、上游限流与协议错误。
- **资源耗尽**：核对连接池、文件描述符、磁盘临时文件、内存和带宽。
- **重启后未恢复**：验证任务真值、resume 入口和状态机是否允许继续。

暂停整个集群时优先关闭领取能力，保留查询和管理面；不要靠断网制造不可控超时。

## 验证与交付

验证队列年龄回落、任务成功完成、失败退款/结算正确、无重复结果、节点指标可区分、缩容实例 active 为零。报告前后拓扑、并发预算、任务样本、排空结果、遗留积压和回滚路径。
