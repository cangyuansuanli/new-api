# 管理对象存储与 CDN

先区分私有对象、公开成品、临时素材和备份，它们不应共享默认访问策略。所有名称、区域、域名、路径前缀、TTL 和供应商能力均从当前配置发现。

## 建立对象契约

确认：

- Bucket、区域、S3 endpoint、公开基础 URL 与自定义域名；
- 对象类别、路径前缀、内容类型、最大体积和保留时长；
- 上传方、下载方、最终所有者和删除责任；
- 私有签名 URL、公开 CDN URL或应用代理 URL 的使用边界；
- CORS 调用源、HTTP 方法、Header 与预签名上传需求；
- CDN cache key、缓存规则、回源鉴权和刷新能力。

不要把短期上游 URL直接发布给最终客户。需要持久结果时，由权威 Worker 下载、校验并转存，再发布自己的稳定 URL。

## 配置 Bucket 与权限

1. 使用专用最小权限身份，分离运行时上传、管理配置、CDN 和备份权限。
2. 默认创建私有 Bucket；只有明确的公开成品前缀才允许公开读取或经 CDN 公开。
3. 为浏览器直传配置精确 Origin、方法和 Header，不使用无边界 `*` 搭配凭据。
4. 为临时对象配置生命周期，并确认规则匹配正确前缀而非整个 Bucket。
5. 设置分片上传清理、版本保留和删除标记策略，估算长期存储成本。
6. 凭据仅写入密钥系统或权限为 `0600` 的环境文件，不输出到日志。

修改生命周期、CORS 或公开策略前先导出现有规则。供应商 CLI 命令成功后仍需重新读取配置确认实际状态。

## 迁移与切换

- 先清点对象数量、总大小、校验信息和数据库引用。
- 使用可重入同步，保留失败清单；大规模迁移分批并限制并发。
- 迁移期间采用双读或旧读新写时，明确唯一写入方和最终收敛步骤。
- 切换前抽样比对大小、ETag/校验和、Content-Type、缓存头和访问权限。
- 更新应用配置后先 canary，确认新对象写入新位置、旧对象仍可读。
- 删除旧存储前等待保留窗口并确认无数据库、队列或历史链接引用。

## CDN 与缓存

只缓存幂等、公开、内容寻址或有明确失效策略的响应。API、鉴权页面、预签名 URL、用户私有资源和错误响应默认不缓存。

发布静态资源优先使用带 hash 文件名和长缓存；HTML/入口清单使用短缓存。刷新时尽量按精确 URL 或前缀，不做无必要的全站清空。验证首个请求为 MISS、后续为 HIT/STALE，并检查回源流量是否下降。

## 验证

端到端验证：

- 服务端上传、浏览器预签名上传、下载和删除；
- 允许 Origin 的 CORS 预检成功，非允许 Origin 被拒绝；
- 私有对象不能匿名读取，公开对象经自定义域名可读取；
- Content-Type、Content-Length、Range、缓存头和 TLS 正确；
- 临时对象生命周期规则命中测试前缀；
- 应用数据库保存的 URL 与实际对象一致；
- CDN 缓存刷新后在供应商预计窗口内生效。

## 交付

报告对象分类、权限主体、生命周期、CORS、CDN 规则、迁移计数、抽样结果、带宽基线和未验证项。不得输出访问密钥、签名 URL 或私有对象列表。
